# 说一声才记：把记笔记做成语音工具

日期: 2026-08-15

## 需求

1. 精听的一问一答和 Live 模式都要支持记笔记，**像播放控制那样**
2. 记笔记必须**显式告知**，不自动记 —— 有些知识点只需要了解，不一定要留
3. 笔记内容必须真正有用，无关内容要过滤掉
4. 要支持词语高亮

## 决定

| 议题 | 决定 |
|---|---|
| 精读的自动沉淀 | **改成显式**，三个场景行为一致 |
| 告知方式 | **语音说出来**（"记下这个词"），不加按钮 |
| 卡片内容 | **老师自己提炼**，填进工具参数 |

第一条推翻了 8-12 的设计决定（当时选的是"自动判断，可以不记"）。理由在下面「与前一版的冲突」。

## 现状

### 播放控制已经是一套完整的工具链路

`save_note` 要走的每一步都已经存在，这是本方案的基础：

```
老师决定调用工具
  → response.function_call_arguments.done
  → RealtimeEventParser.parse → .toolCall(name:args:callId:)
  → ClassroomController: 按 call_id 去重 → runPlaybackTool → sendToolResult(ok:)
  → onNotice(...) 在 dock 上显示一句确认
```

去重是必需的：同一个调用会在专用事件和 `response.done` 里各出现一次
（`handledToolCallIds`）。记笔记比跳转更需要它 —— 重复跳转是无害的，重复记会产生两张
一样的卡片。

### 一个必须先改的技术约束

`RealtimeEventParser.safeArgs` 只解析**数字**参数：

```swift
private static func safeArgs(_ raw: String?) -> [String: Double] {
    ...
    if let d = value as? Double { result[key] = d }
    else if let i = value as? Int { result[key] = Double(i) }
    // 字符串被静默丢弃
}
```

播放控制的参数全是数字（秒数、倍速），所以这个限制从未暴露。`save_note` 必须传文本
（要记的词、释义、例句），所以这一层要先支持字符串，而且**不能破坏现有的数字路径** ——
`playbackTargetPosition` 依赖 `[String: Double]`。

### 高亮已经有可靠的锚定机制

`ExpressionLocator.locate` 按文本搜索定位，而不是信任模型报的字符偏移（那个偏移
「97% 的时候是错的，而且是**似是而非**地错 —— 范围检查能过，高亮落在无关的词上」）。
找不到就返回 nil，宁可不高亮也不误高亮。

这意味着需求 4 几乎是免费的：老师只要报出**词本身**，位置由本地搜索决定。

### 精听现在完全不能记笔记

`ClassroomController.transcript` 累积在内存里，退出即蒸发。精读那套沉淀走的是
`StudyView` 的 `finishConversation`，精听没有对应入口。

## 与前一版的冲突

8-12 的设计里精读是**自动判断、可以不记**，理由是「缺的不是自动化，是判断力」。现在改
成显式，理由是那句话只对了一半：

自动判断解决的是「不该记的别记」，但它同时**拿走了「该记的我说了才记」**。实际用下来
（8-15 设备验证）一次对话结束后是完全静默的：模型判断为空，屏幕上什么都不发生，而
"什么都不记"恰恰是常态。于是「没有需要记的」「还在处理」「出错了」三种状态长得一模一
样。

更根本的是：**知识点值不值得留，取决于你会不会**。同一个词，对你是新的就该记，已经懂
了就不该记 —— 而模型不知道你会什么。它只能猜"一般学习者是否需要"，你却确切知道。

所以显式不是退步。判断力仍然需要（需求 3），但它从"决定要不要记"降级为"决定记什么、
怎么写"——后者模型确实比你强。

## 设计

### 一、工具定义

```
save_note(text, meaning, note_type, example?, why?)
```

| 参数 | 说明 |
|---|---|
| `text` | 要记的词或短语，**必须是原文里出现过的形式**，本地据此定位高亮 |
| `meaning` | 中文释义 |
| `note_type` | `LearningExpressionType` 的取值之一 |
| `example` | 例句，缺省时用宿主句 |
| `why` | 为什么值得记（一句中文） |

不传 `sentence_id`：句子由**当前播放位置**（`cursor()`）决定，和其他播放工具取位置的
方式一致。这也避免了模型报一个不存在的 id。

另一个形态给问答类笔记：

```
save_answer(question, answer)
```

无高亮，对应现有的问答卡。两个工具而不是一个带 `kind` 参数的工具，因为它们的必填字段
完全不同，合成一个会让模型在缺字段时乱填。

### 二、需要改的四处

**1. `safeArgs` 支持字符串**（`RealtimeEventParser`）

改成同时产出 `[String: Double]` 和 `[String: String]`，或改成 `[String: ToolArg]` 枚
举。**约束**：`playbackTargetPosition` 的签名依赖数字字典，现有测试也依赖它，所以数字
路径的行为必须逐字节不变。

**2. `PlaybackTool` 增加两个 case**

名字上它已经不只是"播放工具"了，但改名会牵动整条链路和一批测试，留待需要时再说。

**3. `ClassroomController` 需要一个记笔记的出口**

它现在完全不认识 `EpisodeStore`（刻意的：它是纯逻辑 + transport）。所以不是让它直接写
库，而是加一个回调：

```swift
let onSaveNote: (NoteRequest) -> Void
```

由 `LiveClassSession` 注入，实际落库在那里发生 —— 和 `onNotice`、`onContextRefresh`
同一个模式。控制器保持可测。

**4. 提示词要说清楚什么时候调用**

这是需求 2 和 3 真正落地的地方，比代码更重要：

- **只在被明确要求时调用**。"这个词什么意思"是提问，不是记笔记的请求；"记下这个词"、
  "这个记一下"、"note this down" 才是。
- 不确定时**问一句**，不要猜着记。
- `text` 必须是**原文里的形式**，不要写成词典原形（`worked out` 而不是 `work out`），
  否则本地定位不到、高亮会丢。
- 沿用 `ExtractionPrompt.rejectRules` 的过滤精神：即使被要求记，也不要记问候语、节目
  套话、B2 已知的表达。**但这里的拒绝要说出来**（"这个太基础了，不用记"），而不是静默
  不调用 —— 静默拒绝在显式模式下就是"我说了它没反应"。

### 三、反馈

工具调用完必须有可见确认，这是显式模式的另一半：

- dock 上一句 `onNotice`（"已记下 kind of"）—— 复用播放控制那套，会自己消失
- 精读里对话面板下方同样显示

「说了但没记」和「说了没听见」必须能区分。这正是自动模式下缺失的东西，不能在新模式里
重复。

### 四、精读怎么改

`finishConversation` 不再自动提炼。`KnowledgePointExtractor` 和
`ExtractionPrompt.conversationRules` 会失去唯一调用方 —— 但**先不删**：显式模式上线后
如果发现"我经常忘了说记一下"，自动沉淀会作为补充回来，那时它们还在。这与之前删死代码
的做法不同，因为这次是行为决策的试验，不是清理确定无用的东西。

`ReadingAsk` 保留（对话状态、追问、可见的等待状态都还需要）。

### 五、测试

纯逻辑层：

- `safeArgs` 同时解析数字和字符串，且数字路径不变（回归）
- 工具名解析（`save_note` / `save_answer` 认得，未知名字仍然返回 nil）
- 同一 `call_id` 只记一次（去重）
- `NoteRequest` → DTO 的映射，含 `note_type` 未知值的兜底
- 定位失败时仍然存卡但不带高亮（复用 `ExpressionLocator` 已有行为）

必须真机验证（单测无法回答）：老师在被要求时**真的会调用**这个工具，而不是只用嘴回答
"好，我记下了"。这是本方案最大的风险 —— 见下。

## 风险

**最大风险：老师说"记下了"但不调用工具。** 这是提示词能否驯服模型的问题，代码层面无
法保证。播放控制有同样的先例，而且当时需要一条很重的指令才压住
（`playbackDisambiguationRules` 里的 "Use the registered tools instead of merely
describing actions"）。记笔记要复用这条措辞。

如果提示词压不住，退路是加一个按钮（本轮明确不做，但它是可行的兜底）。

**次要风险**：`safeArgs` 的改动动到了所有工具调用的公共路径。数字路径必须有回归测试
钉住，否则播放控制会被记笔记的需求带坏。

## 未纳入范围

- **复习入口** —— 仍然没有。显式记笔记会让卡片变多，这条的价值随之上升
- **精听的对话文字显示** —— 精听现在只有 dock 上的一句话，没有精读那样的对话面板
- **`PlaybackTool` 改名** —— 它已经名不副实
