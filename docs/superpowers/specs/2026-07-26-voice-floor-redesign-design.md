# 语音课堂重设计:两个独立入口 + 发言权仲裁

日期:2026-07-26
状态:已通过 brainstorming,待实现

## 背景与问题

第一版讨论 UI 把"进入模式"和"每一轮发言"压进了同一个长按手势:长按说话、长按中上滑锁定进 live。真机使用后体验不自然,根本原因有二:

1. **交互层面**:push-to-talk 是对讲机模型,每句话都要按住不放,和"对话"的心智模型冲突;live 被藏在长按里的上滑动作,既难发现又难触发。
2. **架构层面**:播客暂停/恢复、老师说话、你说话这三件事没有统一的"发言权"仲裁,散落在 `ClassroomController` 各处的 `pause()` / `stopSpeaking()` / `play()` 调用里,导致声音会叠加、该停的没停、该续的没续。

## 第一性原理

用户校准出的核心定位:

- **两种模式都要,且平级独立**:随手插一句(push-to-talk)是主旋律,深聊(live)也要。
- **"可控"= 模式的进入/退出边界清晰、由用户决定**(不是每轮发言都要动手)。参照豆包。
- **灵魂铁律**:*同一时刻只有一方发声,但形式自由。* 播客、老师、用户三者轮流出声,永不打架。

## 架构总览

三个隔离的关注点:

1. **两个独立入口**(手势层):长按=插话,点击=进入 live。互不嵌套。
2. **发言权令牌**(状态层):唯一的 floor token,同一时刻只在播客/用户/老师之一手里。声音单声道由令牌换手时统一执行,不再靠散落的调用拼凑。
3. **视觉反馈**(呈现层):令牌持有者 ⟷ 唯一一种视觉状态,用户瞟一眼就知道该说、该等、还是在放。

## 组件一:两个独立入口(手势层)

悬浮按钮承载两个独立手势(取代"长按里藏上滑"):

- **长按 = 插话(quick ask)**
  - 按住 → 播客立即暂停 → 用户说话 → **松手立即结束,老师马上答** → 答完自动续播。
  - 松手即答(不加宽限期):心智模型是"按着=我说,松开=换你"。
  - 适合从"安静听"里临时问一句。
- **点击 = 进入 Live**
  - 点一下 → 进入持续对话模式(见组件三)。
  - 退出 Live 通过点击退出按钮,回到 app 正常听播客状态。

两条路完全独立、互不嵌套。不再有"长按到一半上滑锁定"这类隐藏动作。这同时满足"A 和 B 都要":长按=B(插话),点击=A(持续)。

## 组件二:发言权令牌(状态层)—— 地基

引入唯一的 **floor token**,同一时刻只在三方之一手里:`player` / `user` / `teacher`(外加一个 `idle` 空置态)。

**规则:令牌交给谁,只有谁出声,另两方静音。** 交接由明确事件驱动:

| 事件 | 令牌 → | 副作用(换手时统一执行) |
|---|---|---|
| 用户开口 / 长按按下 | user | 播客暂停、老师闭嘴(`stopSpeaking`) |
| 用户说完(松手 or live 里停顿) | teacher | 请求老师回答;播客保持暂停 |
| 老师答完 | 视场景 | 插话场景:还给 player 续播;live 场景:idle,等用户 |
| 用户说"继续播放" | player | 老师闭嘴,播客续播 |
| 用户说"停一下" | idle | 播客停,等用户 |
| 退出 live | — | 断开,回到正常听播客 |

**收益**:"声音永远单声道"这条铁律,从换手函数一处统一保证,而不是东一处西一处拼凑。谁响谁闭,只有一个地方决定(单一事实来源)。

**技术落点**:替换 `ClassroomController` 里散落的暂停/恢复/打断逻辑,收拢成"当前令牌持有者"状态 + 一个交接函数 `grantFloor(to:)`。现有 `classroomReducer` 状态机尽量复用,主要是把"谁有发言权"提升为显式的单一状态。交接函数负责:让新持有者出声、令另两方闭嘴。

## 组件三:Live 模式的内部行为

点击进入后是"共同在场"空间。初始播客暂停,之后全程靠用户的话自由调度。

**声音三态由令牌轮转:**

| 用户做什么 | 令牌 | 结果 |
|---|---|---|
| 进入 Live | idle | 播客暂停,老师在线待命,等用户 |
| 直接开口说话 | user | VAD 听到→(若播客在放)立即压下播客→老师听 |
| 停顿(自然说完) | teacher | 老师接话回答 |
| 说"继续播放"/"接着放" | player | 老师闭嘴,播客续播,用户仍可随时插话 |
| 说"停一下" | idle | 播客停,等用户 |
| 点退出按钮 | — | 断开 Live,回到正常听播客 |

**关键点:**
- Live 里**张嘴即说**,不碰屏幕。播客在放时用户一开口,VAD 检测到就压播客。
- "继续播放/停一下/跳到某处"都是**说出来的**,老师调用播放工具执行(function-call 链路,已在 commit 3389b78 修复:解析 `response.function_call_arguments.done`)。
- 退出 Live 是 live 内唯一需要点击的动作。

**技术风险(必须真机验证):** Live 里"张嘴即说"依赖回声消除干净——播客从扬声器出、被麦克风收回,不能被误判为"用户在说话"。iOS `voiceChat` 模式有硬件回声消除,理论可行,但必须真机验证。若消除不干净,会出现"播客把自己打断"的抽风。兜底:live 里播客播放时调低 VAD 灵敏度,或退一步"点一下再说"。先按"张嘴即说"实现,真机测。

## 组件四:视觉反馈(令牌可见)

令牌持有者 ⟷ 唯一视觉状态,用户瞟一眼就知道现在该说/该等/在放:

| 状态 | 令牌 | 视觉 |
|---|---|---|
| 正常听播客(未进任何模式) | player | 安静的悬浮波形按钮 |
| 长按插话中 | user | 图标放大 + 录音感("在听你") |
| 老师在回答 | teacher | 声纹跳动("它在说") |
| Live 待命 / 用户说 / 老师说 | 轮转 | dock 常驻,用同一套三态视觉表示当前持令牌者 |

核心原则:同一时刻的令牌持有者,对应唯一一种视觉。

## 与现有实现的关系

- **保留**:transport 层的两种回合模式(continuous / pushToTalk)、mic 门控、function-call 解析与去重(commit 3389b78)、真机签名配置。
- **重写**:`ClassroomController` 的播放控制逻辑,收拢为 floor token + `grantFloor(to:)`。
- **重写**:`DiscussionDockContent` 的手势层,从"长按+上滑锁定"改为"长按=插话、点击=live"两个独立入口。
- **调整**:`LiveClassSession` 进入 live 时的初始状态(播客暂停、令牌 idle)。

## 测试策略

三层各自可独立单测(延续现有模式):

1. **令牌交接(逻辑层,纯函数)**:给定当前持有者 + 事件 → 新持有者 + 应静音的方。覆盖表格里每一行。这是"单声道铁律"的测试锚点。
2. **控制器**:长按按下→令牌给 user+播客暂停;松手→令牌给 teacher+请求回答;老师答完(插话场景)→续播;live 里"继续播放"→令牌给 player。
3. **手势层**:长按触发 begin/endUserTurn;点击触发进入 live。

**无法单测、需真机验证**:回声消除是否干净(live 张嘴即说不被播客误触发);声音是否真的从扬声器出;整条 live 轮转的实际手感。

## 明确不做(YAGNI)

- 不做长按中上滑锁定(被两个独立入口取代)。
- 不做文字输入、insight capture(前一版已删除,保持)。
- 不做 anchor seeking(讨论始终锚定当前播放位置)。
- 不做首次连接的蓄力环(deferred;不阻塞本次核心体验)。
